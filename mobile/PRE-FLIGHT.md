# Mobile store cutover — pre-flight checklist

> **Just want an installable build right now (no store)?** Skip this — see
> [`docs/mobile/README.md`](../docs/mobile/README.md). A debug APK and an
> iOS simulator build work today with no accounts (`npm run apk` / `npm run ios:sim`).
> **This file is about the public _store_ cutover**, which is still account-blocked.

> Readiness audit + step-by-step runbook for the first TestFlight + Play Internal Track push. Documents everything an operator needs so the actual cutover is mechanical.

Status as of 2026-06-02: **infrastructure ready, blocked only on external account creation + binary-asset production**. The Fastlane lanes are written, the `release-ios.sh` + `release-android.sh` scripts work end-to-end pending credentials, the iOS + Android native scaffolds are checked in, and `npm run mobile:ios` + `npm run mobile:android` open the platform IDEs cleanly off `web/dist`.

**landed:** iOS `Info.plist` now declares `arm64` (was `armv7`, App Store reject), `ITSAppUsesNonExemptEncryption=false`, `LSApplicationCategoryType=public.app-category.travel`. iOS `Podfile` lists `CapacitorShare` + `CapacitorHaptics`. `Podfile.lock` is committed (deterministic CI). Android release `buildType` runs `minifyEnabled true` + ProGuard, reads keystore creds from gitignored `keystore.properties`, and consumes `VERSION_CODE` from env. `AndroidManifest.xml` enforces `usesCleartextTraffic="false"` + `allowBackup="false"`. Native splash + launch screen branded to FWP Blue `#002855`. `@capacitor/assets` replaces deprecated `cordova-res`.

## Cutover runbook

### One-time prep

```bash
# Install local tooling.
brew install fastlane cocoapods
brew install --cask android-studio    # if not already installed

# Verify Capacitor toolchain (from the repo root).
cd mobile
npx cap doctor      # reports any missing native bits
```

### Dry-run build (no upload)

```bash
# From repo root.
npm run mobile:ios       # → web build, cap sync, opens Xcode
npm run mobile:android   # → web build, cap sync, opens Android Studio
```

In Xcode: select iPhone 15 Simulator → ⌘R. Confirm splash, status bar, and app icon render.
In Android Studio: select a Pixel 7 emulator → ▶. Same checks.

### TestFlight push (after iOS credentials in place)

```bash
cd mobile/ios
fastlane ios beta
```

Lane will:

1. Bump build number.
2. Build web (`npm run build --workspace web`).
3. `cap sync ios`.
4. Match-resolve signing.
5. `build_app` → IPA.
6. Upload to TestFlight, no review submission.

Invite testers in App Store Connect → TestFlight → Internal Testing → add by Apple ID.

### Play Internal Track push (after Android credentials in place)

```bash
cd mobile/android
fastlane android internal
```

Lane will:

1. Build web.
2. `cap sync android`.
3. Gradle `:app:bundleRelease` → AAB.
4. Upload to Internal Track, status `draft`.

Promote to testers in Play Console → Testing → Internal Testing → Manage testers → add by email.

## Smoke tests after first install

Run on a real device (or simulator/emulator if no device available):

- [ ] App launches; splash shows FWP Blue + wordmark; transitions cleanly to map.
- [ ] Status bar reads dark blue with light text.
- [ ] First-run privacy notice appears, dismisses, persists.
- [ ] Map renders; layer toggles open/close on tap.
- [ ] Locate-me prompts for location permission; coords stay on device (verify with Charles Proxy or Mitmproxy — no GPS to network).
- [ ] Field-mode toggle works; UI shifts to high-contrast.
- [ ] Offline-tile download UI opens; "Download" works for a small region.
- [ ] Dark mode toggle survives app restart.
- [ ] Bottom safe-area not clipped on iPhone notch / Android gesture bar.
- [ ] All 3 tabs (Hunt / Explore & Access / My FWP) load.
- [ ] Tap a feature → bottom sheet morphs into view.
