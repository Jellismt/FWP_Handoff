# File Header Convention

> **This is a convention, not a gate.** The header banner is not enforced by an
> automated check, so `npm run verify` stays focused on correctness gates and a
> new or renamed file never fails the build until decorated. The headers are useful top-of-file
> documentation; keep following the pattern below for new files as a courtesy to
> the next maintainer, but nothing blocks a commit if you don't.

Existing `.tsx`, `.ts`, and `.css` files in `web/src/` (and `.ts` files in
`mobile/`) carry a header in this form; match it for new files:

```js
/**
 * @file ComponentName.tsx
 * @module engage-mt/[module-name]
 * @description Brief description of what this file does.
 * @author Jamie Ellis / Engage MT
 * @created YYYY-MM-DD
 * @updated YYYY-MM-DD
 * @version 1.0.0
 *
 * FWP Engage MT — Montana's Official Gateway to the Outdoors
 * Licensed under the MIT License.
 */
```

## Rules

- `@file` — exact basename of the file (e.g. `MapView.tsx`).
- `@module` — `engage-mt/` plus the slice of the app: `map`, `fish`, `hunt`, `explore`, `manage`, `shared`, `hooks`, `store`, `services`, `config`, `styles`, `utils`, `types`.
- `@description` — one sentence. Explain the *purpose*, not the implementation.
- `@author` — `Jamie Ellis / Engage MT` for all session output.
- `@created` — ISO date the file was first written.
- `@updated` — bump to today's ISO date whenever you materially edit the file.
- `@version` — semver, starting at `1.0.0`. Bump minor when adding capability, major when changing the contract.

## CSS variant

For `.css` files, use the same block but as a CSS comment:

```css
/**
 * @file brand-tokens.css
 * @module engage-mt/styles
 * @description FWP brand color and typography tokens (light + dark mode).
 * @author Jamie Ellis / Engage MT
 * @created 2026-05-29
 * @updated 2026-05-29
 * @version 1.0.0
 *
 * FWP Engage MT — Montana's Official Gateway to the Outdoors
 * Licensed under the MIT License.
 */
```

## Generated files

Files generated by tooling (Vite bundles, Capacitor scaffolds, `dist/`) are exempt. So are `.json`, `.html`, `.sh`, and `.md` files.

## Consistency guidance (not enforced)

When you follow the convention, keep these consistent so the headers stay useful:

- `@module` should track the file's location — the part after `engage-mt/` mirrors
  the directory under `web/src/` with the `components/` segment elided
  (`components/hunt/…` → `engage-mt/hunt`; deeper is fine:
  `engage-mt/map/featureCards`). If you move a file, update its `@module`.
- `@updated` — bump to today when you materially edit a file.
- `@version` — plain `N.N.N` semver.

## Why keep them

Auditors, future contractors, and downstream FWP teams inherit this code. The
header makes ownership, intent, and last-touched date immediate at a glance —
worth the few seconds on a new file even without a gate forcing it.
