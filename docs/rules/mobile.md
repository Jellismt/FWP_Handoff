## Native app-lifecycle (M1)

`@capacitor/app`, `@capacitor/status-bar`, and `@capacitor/splash-screen` are
driven at runtime from two guarded services mounted once in `App.tsx`:

- [`services/mobile/appLifecycle.ts`](../../web/src/services/mobile/appLifecycle.ts) — wires the
  Android hardware **Back button** (pops router history; only exits at a tab
  root per `ROOT_PATHS`), **resume-from-background** (re-checks time-sensitive
  state like connectivity + the closure/advisory feed), and **deep links** (`engagemt://…` custom scheme + `https://…/app/…`
  universal links → React Router). Pure helpers `resolveBackAction` +
  `deepLinkToPath` are unit-tested.
- [`services/mobile/nativeChrome.ts`](../../web/src/services/mobile/nativeChrome.ts) — keeps the
  WebView **below** the status bar (`setOverlaysWebView({ overlay: false })`, so the
  header never clips under it) and hides the launch splash once React paints. The
  status bar is deliberately **not** re-tinted per theme or per module. On **iOS**
  it sets light glyphs once (`Style.Dark`) for the fixed FWP-Blue `#002855` strip;
  on **Android 15 / API 35** the OS ignores status-bar colour APIs and the WebView
  doesn't bridge insets to CSS, so the bar is left as the system default and no
  per-theme repaint is attempted (neither platform tracks the app theme at the
  native layer). Relatedly, iOS
  requires `ios.contentInset: "never"` in `mobile/capacitor.config.ts` — with the
  default `"automatic"`, WKWebView auto-insets its scroll view and zeroes every
  `env(safe-area-inset-*)`, silently breaking the header's safe-area padding.

Both follow the guard pattern (no-op on web; plugins dynamically
imported only under `isCapacitor()`).

### Deep links, shared files, and native registration

`appLifecycle.ts` handles three inbound URL kinds via the pure, tested
`classifyLaunchUrl` (and `getLaunchUrl` for cold starts):

- **deep-link** — `engagemt://…` / `https://fwp.mt.gov/app/…` → `deepLinkToPath`
  → React Router. Includes shared pins at **`/field/receive?d=<payload>`**.
- **share-file** — a `file://` / `content://` `.gpx`/`.kml` opened from the OS →
  `sharedFileImport.stageSharedFileImport` (guarded @capacitor/filesystem) →
  `pendingImportStore` → the import preview on Field Tools.
- **external-guidance** — an external third-party mapping-app share link
  (non-`fwp.mt.gov`, undecodable) → receive-page guidance.

**Native registration is required and lives in the tracked config files:** the
`engagemt://` URL scheme + GPX/KML document types in
`mobile/ios/App/App/Info.plist` (`CFBundleURLTypes` / `CFBundleDocumentTypes` /
`UTImportedTypeDeclarations`) and `mobile/android/app/src/main/AndroidManifest.xml`
(`<intent-filter>` for the scheme, App Links, and `.gpx`/`.kml` VIEW/SEND). Without
these, deep links and "open in Engage MT" don't route. Universal links additionally
need an Associated-Domains entitlement (iOS) + `/.well-known/assetlinks.json`
(Android) on fwp.mt.gov — the custom scheme works standalone.

## Source of truth

The mobile app is **the web build wrapped**. `mobile/capacitor.config.ts` points `webDir: "../web/dist"`. There is no separate mobile React tree — features ship to web first, then sync to mobile.

## Build → sync → open pipeline

The canonical commands, from the repo root:

```bash
npm run mobile:ios       # ↳ runs scripts/sync-and-open-ios.sh
npm run mobile:android   # ↳ runs scripts/sync-and-open-android.sh
```

Each script does:

```bash
cd web && npm run build && cd .. \
  && cd mobile && npx cap sync && npx cap open <platform>
```

Never call the underlying steps individually as a habit — the script enforces the order.

`npx cap sync` **generates/updates the native Gradle (`mobile/android/`) + Xcode
(`mobile/ios/`) projects** from `web/dist` and syncs plugin native code — that generated
project is then built by the native SDK (Android SDK/Gradle → APK/AAB, Xcode → IPA).

## Platform projects

`mobile/ios/` and `mobile/android/` are generated by `npx cap add`. **Track only the config bits** (`Info.plist`, `AndroidManifest.xml`, `build.gradle`, `Podfile` deltas you intentionally edit). The generated Xcode/Gradle scaffolds are recreatable.

Gitignore excludes `mobile/ios/App/Pods/`, `mobile/ios/App/build/`, `mobile/android/.gradle/`, `mobile/android/app/build/`.

## On-device-only location

User location stays on device. **Never** ship coordinates to FWP servers, analytics, or any third party. This is a hard rule from the security spec.

Geolocation access uses `@capacitor/geolocation` with `enableHighAccuracy: true` for hunt/fish use cases. It is wrapped in the `useLocate` hook (`web/src/hooks/useLocate.ts`) — Capacitor Geolocation on native, `navigator.geolocation` fallback on web — which watches for up to four seconds and keeps the most accurate fix (returning early at 20 m) so the map never flies to the first coarse cell-tower answer, and returns coordinates only to the in-process caller (never persisted, never transmitted).

### GPS track recording

Recording (`web/src/services/field/trackRecorder.ts`) is **foreground-only**, and that is a product decision rather than a platform limit — a Capacitor plugin is native code with a JavaScript handle, and background-geolocation plugins for this Capacitor major do exist. What is not free is the cost: an Android foreground service with a permanent notification, `ACCESS_BACKGROUND_LOCATION` and `POST_NOTIFICATIONS`, the iOS location background mode with an Always purpose string and its status-bar indicator, a Play Console background-location declaration with a demo video, an App Store justification under guidelines 2.5.4 and 5.1.5, and licensing — there is no MIT-licensed option validated on this Capacitor major. It also changes what [privacy.md](privacy.md) tells users. `check:native-config` fails the build if `ACCESS_BACKGROUND_LOCATION` is ever declared without the foreground service, notification permission, and iOS purpose string behind it, because that exact half-declaration shipped once before and is a store-review rejection trigger. While recording, the screen is held awake by `@capacitor-community/keep-awake` on the device and by the Screen Wake Lock API in a browser (`services/mobile/keepAwake.ts`, re-acquired when the tab returns to the foreground). A pause, a lock, or a silence longer than two minutes starts a **new segment** (`CapturedRoute.segments`) — the map draws one path per segment and GPX export writes one `<trkseg>` per segment, so a gap is never bridged by a straight line and never counted as distance. Each track records the **median horizontal accuracy** of its fixes (`accuracyMedianM`, shown on the track card); elevation gain only counts climbs larger than the reported vertical error (or about 3 m), measured from a moving anchor.

### Offline tiles on disk

Tiles are written as ordinary image files under the app data directory
(`tiles/{areaId}/{z}/{x}/{y}.{png|jpg}`), with the extension matching what the
source serves. Two rules matter when touching `tileDownloader.ts`. The
filesystem plugin decides how to treat `data` from whether `encoding` is
present: absent means "this is base64, decode it to bytes", present means
"this is text" — so binary tiles pass no encoding and JSON manifests must pass
`utf8`, or the write is rejected and silently lost. Use the module's
`writeBytes` / `writeText` helpers rather than calling `writeFile` directly.
And tiles are read by URL, not by content: `offlineTileResolver.ts` resolves
the served base once through `Capacitor.convertFileSrc` and hands the map plain
URLs, so no tile crosses the plugin bridge as base64.

**Known gap, needs native code.** `Directory.Data` is the iOS Documents
directory, which is included in iCloud and Finder backups. A full offline pack
is up to 2 GiB of tiles that can be re-downloaded from USGS at any time, so it
should carry `NSURLIsExcludedFromBackupKey`; Apple's data-storage guidelines
expect exactly that for regenerable content. The Filesystem plugin exposes no
backup-exclusion option, so this needs a small native plugin — moving the tree
to `Directory.Cache` is not a fix, because iOS may purge it out from under
someone already in the field. Android is unaffected: `AndroidManifest.xml` sets
`allowBackup="false"`.

### Photos

Waypoint photos are redrawn through a canvas before they are stored (`downscaleDataUrl`), which strips EXIF (position, device) and caps the long edge at 2048 px; the native camera is asked for the same size with orientation corrected. On the web, photos live in localStorage as data URLs, so the library keeps a 3 MB budget and refuses a photo that would exceed it with a `PhotoQuotaError` (shown as a toast) rather than failing silently at the browser quota.

## Permissions

Declare minimums in `Info.plist` (iOS) and `AndroidManifest.xml` (Android):

- Location (when in use)
- Camera (waypoint photos in field tools)
- Filesystem (offline map tiles)

Each declaration uses FWP-voice copy explaining *why* the permission is needed.

## Capacitor + ArcGIS interop

ArcGIS Maps SDK 5.x runs fine in the Capacitor webview. Watch for:

- WebGL context — Calcite's `<calcite-mode-dark>` plus a dense ArcGIS map view can stress older devices. Test on a 3-year-old Android baseline.
- **Memory / `largeHeap`.** `mobile/android/app/src/main/AndroidManifest.xml` declares `android:largeHeap="true"`, and `check:native-config` enforces it. Be precise about what that does: it raises the **app process's Java heap**, and it was added after a `java.lang.OutOfMemoryError` on first map render — a single large Java-side allocation against a 192 MB growth limit. It does **not** govern the WebView's WebGL, texture, or JavaScript memory: Android runs the WebView renderer in a separate sandboxed process whose allocations are native, not Java, and `largeHeap` never touches them. So the flag is a mitigation for one unbudgeted allocation, not a ceiling imposed by the JS SDK, and a native SDK would face the same device memory budget with its buffers in the same native pool.

  Treat it as removable-with-evidence rather than permanent. To drop it, measure on a low-RAM Android baseline (a real device or a host-GPU emulator — software GL invalidates the comparison) with the flag still on: peak Dalvik heap through first map render via `adb shell dumpsys meminfo <pkg>`, compared against `ActivityManager.getMemoryClass()`; the WebView renderer process separately, since the app-package dump excludes it; and retained `MapView`/`Layer` counts across ten navigations away from `/` and back, via a V8 heap snapshot in `chrome://inspect`. Memory is still the dominant runtime cost — budget new layers and offline packs against it.
- Asset paths must be HTTPS or relative — Capacitor blocks `http://` by default.

## Splash & status bar

`@capacitor/splash-screen` shows the FWP-branded launch splash — the **ENGAGE /
MONTANA** wordmark (FWP Blue `#002855` ground, "ENGAGE" in the FWP Yellow
`#FFC72C` arrow chip, "MONTANA" on the line below). The per-density assets are
committed; regenerate them from the masters in `mobile/assets/` with
`npx @capacitor/assets generate --ios --android`. It's hidden
by `nativeChrome.hideSplash()` once React paints. `@capacitor/status-bar` is set
**once** (not per-route): WebView below the bar, iOS light glyphs — see the
native-chrome service above.

## Platform guards (the `isCapacitor()` rule)

Any code that imports a `@capacitor/*` plugin must guard at the entry point with `isCapacitor()` from [`web/src/utils/capacitor.ts`](../../web/src/utils/capacitor.ts) — otherwise the web build throws `Plugin "X" is not implemented on web` the first time the path is hit.

Three flavors:

1. **Hard guard, no-op on web** — native haptics, GPS track recording, offline area download. Return early; the feature simply isn't available.
2. **Soft guard, web fallback** — filesystem → `localStorage`, share-sheet → Web Share API. Web path is a real implementation, not a stub.
3. **Dynamic-import guard** — `await import("@capacitor/...")` *inside* the guarded branch when the plugin's load itself is expensive on web.

DON'T:
- Don't add `// TODO: web fallback` and ship — runtime errors fire in dev.
- Don't gate UI on `isCapacitor()`. Feature-detect at the *capability* level (`if (!navigator.geolocation)`).
- Don't import Capacitor plugins from React components — wrap in a service module so the guard lives in one place.

### Semantic capability predicates (the web/mobile field-tool boundary)
When a whole *product capability* (not just a plugin import) is mobile-only, gate
it through a **named predicate** in [`web/src/utils/capacitor.ts`](../../web/src/utils/capacitor.ts)
rather than a bare `isCapacitor()` in JSX. Today:

- `supportsGpsCapture()` — GPS **track recording** (the `RecordingStatusChip` HUD,
  `TrackRecorderPanel`, the Capture cluster's record-track). Mobile-only.
- `supportsOfflineDownload()` — **offline tile** area download. Mobile-only.

**Waypoint dropping is NOT gated** — the rail tool, the
`attachWaypointDrop` long-press/right-click gesture, and the tap-query "Drop a
waypoint here" action work on web + mobile. Web pins persist to `localStorage`
and go to the phone via **Send to phone** (`SendToPhoneDialog`, same-origin
`/field/receive` link). So the web app is still a **planning surface** — plan by
drawing + measuring + dropping pins — but it hides only the Capture cluster + the
Offline-maps nav. One predicate change re-scopes what web offers, so **don't**
sprinkle raw `isCapacitor()` at these seams — read the predicate. The per-platform
tool set is regression-guarded by `web/src/components/map/MapToolRail.test.tsx`.

## Builds — the command surface

There is **one canonical way to get each kind of build** — don't hand-roll `gradlew` / `xcodebuild` invocations in new
scripts; extend these.

| Command | Produces | Needs |
|---|---|---|
| `npm run mobile:doctor` | toolchain readiness table (✅/❌ + fixes) | nothing |
| `npm run mobile:bootstrap` | installs JDK 21 + Android SDK + CocoaPods + fastlane | macOS + Homebrew |
| `npm run apk` | Android **debug** APK (unsigned, sideloadable) | Android toolchain |
| `npm run ios:sim` | iOS **simulator** app | Xcode + CocoaPods |
| `bash mobile/scripts/gen-keystore.sh` | release keystore + `keystore.properties` (gitignored) | JDK |
| `bash mobile/scripts/release-android.sh [--apk]` | signed AAB (or `--apk` standalone APK) | keystore |
| `bash mobile/scripts/release-ios.sh` → `fastlane ios beta` | device IPA / TestFlight | **Apple enrollment (J-021)** |

**Signing discipline.** The release keystore is the one irreplaceable secret — generated by
`gen-keystore.sh`, gitignored, and never stored in any build system (losing it orphans the Play
listing forever). The Android Gradle build reads it from `mobile/android/keystore.properties`
(rootProject) — keep any path reference in lockstep with `mobile/android/app/build.gradle`.

**Still account-blocked (not solvable in-repo):** Apple Developer enrollment (J-021) for any
iPhone-device/TestFlight build; Google Play Console (J-022) for a Play listing. Everything
else — a downloadable APK and an installable simulator build — works today with no accounts.
See [`mobile/PRE-FLIGHT.md`](../../mobile/PRE-FLIGHT.md) for the store-cutover detail.
