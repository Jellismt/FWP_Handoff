# Store release — signed builds, keys, and accounts

What it takes to ship Engage MT to the Play Store and the App Store. Debug and
simulator builds ([building.md](building.md)) need none of this.

## What the agency must own

| Item | Who | Notes |
|---|---|---|
| **Google Play Console account** | the publishing agency | $25 one-time, organization account |
| **Apple Developer Program enrollment** | the publishing agency | $99/yr; organization enrollment needs a D-U-N-S number |
| **Android upload keystore** | the publishing agency — **generate your own** | see below; never accept a keystore generated by someone else |
| **App Store Connect API key** (for fastlane) | the publishing agency | created after Apple enrollment |
| Icon/splash source assets | design | masters in `mobile/assets/`; see `mobile/NATIVE-ASSETS.md` |

## Android

### 1. Generate the release keystore (once, and back it up)

```bash
bash mobile/scripts/gen-keystore.sh
```

Interactive: creates the keystore and `mobile/android/keystore.properties`
(both gitignored) and reminds you to back them up. The Gradle release build
reads the properties file from `mobile/android/`.

**You generate this yourselves and own the password.** Keep the keystore out
of every build system and out of the repo; store it (plus the password) in your secrets
management, with an offline backup.

### 2. Enable Play App Signing (strongly recommended)

When creating the Play listing, accept **Play App Signing** (the default for
new apps). Google then holds and backs up the *app signing key*, and your
keystore is only the **upload key** — losing it becomes a recoverable
"request an upload-key reset" instead of permanently orphaning the listing.
Upload the **AAB** so Play can re-sign for delivery.

### 3. Build the signed artifact

```bash
bash mobile/scripts/release-android.sh          # → signed AAB (upload to Play Console)
bash mobile/scripts/release-android.sh --apk    # → signed standalone APK (direct sideload)
npm run verify:signing                          # confirm the artifact is correctly signed
```

`versionCode` comes from the `VERSION_CODE` environment variable (your
release pipeline's build number is a good source); `versionName` lives in
`mobile/android/app/build.gradle`.

## iOS

Everything is wired; it activates once Apple Developer enrollment exists.

```bash
# After enrollment: fill mobile/.env.local + mobile/ios/fastlane/Appfile
# and place the App Store Connect API key (AuthKey_*.p8)
bash mobile/scripts/release-ios.sh      # web build → cap sync → xcodebuild archive
cd mobile/ios && fastlane ios beta      # upload to TestFlight
```

- Signing uses the App Store Connect API key (no interactive Apple login, so
  the lane runs unattended).
- TestFlight is the recommended staging path before App Store review.
- The iOS privacy manifest required for submission is in the repo and gated by
  `npm run check:ios-privacy-manifest`.

## Release checklist (both platforms)

1. `npm run verify` green at the release commit.
2. **Refresh the bundled regs snapshot** — the store build is many users'
   offline floor ([../deploy/data-refresh.md](../deploy/data-refresh.md));
   `npm run check:regs-floor` warns if it's stale.
3. Bump `versionName` / iOS version + build number.
4. Build signed artifacts; run `npm run verify:signing` (Android).
5. Smoke-test the signed build on a physical device (map render, district
   detail online + airplane mode, waypoint drop, dark mode).
6. Upload (Play Console AAB / TestFlight).

## Store-config sanity gates

`npm run check:native-config` asserts app id (`gov.mt.fwp.engagemt`), version,
and signing config stay coherent across `capacitor.config.ts` and the native
projects; `npm run check:plugin-parity` pins Capacitor plugin versions between
`web/` and `mobile/`. Both run inside `npm run verify`.
